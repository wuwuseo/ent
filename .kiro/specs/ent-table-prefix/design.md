# 设计文档

## 概述

本设计文档描述了 Ent 表前缀扩展的技术实现方案。该扩展通过 Ent 框架的扩展机制和模板系统，在代码生成阶段为所有实体的数据库表名添加统一前缀。

核心设计理念：
- 最小侵入性：不修改 Ent 核心代码，通过扩展机制实现
- 声明式配置：通过简单的函数调用配置前缀
- 模板驱动：利用 Go 模板生成表名转换代码

## 架构

### 整体架构

```
┌─────────────────────────────────────────┐
│         用户的 Ent 生成入口              │
│    (ent/generate.go 或类似文件)         │
└──────────────┬──────────────────────────┘
               │
               │ 注册扩展
               ▼
┌─────────────────────────────────────────┐
│      TablePrefixExtension               │
│  ┌───────────────────────────────────┐  │
│  │  - prefix: string                 │  │
│  │  - Templates() []*gen.Template    │  │
│  └───────────────────────────────────┘  │
└──────────────┬──────────────────────────┘
               │
               │ 提供模板
               ▼
┌─────────────────────────────────────────┐
│      Ent 代码生成器 (entc)              │
│  - 解析 Schema                          │
│  - 应用扩展模板                         │
│  - 生成代码文件                         │
└──────────────┬──────────────────────────┘
               │
               │ 使用模板
               ▼
┌─────────────────────────────────────────┐
│    tableprefix.tmpl 模板                │
│  - 遍历所有实体                         │
│  - 为每个实体生成表名钩子方法           │
│  - 应用前缀到表名                       │
└──────────────┬──────────────────────────┘
               │
               │ 生成代码
               ▼
┌─────────────────────────────────────────┐
│      生成的 Go 代码文件                 │
│  - 包含表名转换逻辑                     │
│  - 自动应用于所有实体                   │
└─────────────────────────────────────────┘
```

### 组件交互流程

1. **配置阶段**：用户调用 `WithTablePrefix("prefix_")` 创建扩展实例
2. **注册阶段**：将扩展实例传递给 `entc.Generate()` 的 Extensions 选项
3. **生成阶段**：Ent 代码生成器调用扩展的 `Templates()` 方法获取模板
4. **渲染阶段**：模板引擎处理 `tableprefix.tmpl`，生成表名转换代码
5. **输出阶段**：生成的代码写入到 `ent/generated` 目录

## 组件和接口

### 1. TablePrefixExtension 结构体

```go
type TablePrefixExtension struct {
    entc.DefaultExtension  // 继承默认扩展
    prefix string          // 存储表前缀
}
```

**职责：**
- 实现 Ent 的 Extension 接口
- 存储表前缀配置
- 提供模板注册功能

**接口实现：**
- `Templates() []*gen.Template`：返回表前缀模板列表

### 2. WithTablePrefix 函数

```go
func WithTablePrefix(prefix string) *TablePrefixExtension
```

**参数：**
- `prefix string`：要应用的表前缀字符串

**返回值：**
- `*TablePrefixExtension`：配置好的扩展实例

**职责：**
- 创建并初始化 TablePrefixExtension 实例
- 验证前缀参数的有效性
- 返回可用于 entc.Generate 的扩展对象

**实现细节：**
- 如果 prefix 为空，仍然创建扩展但不修改表名
- 支持任意合法的 SQL 标识符字符
- 不自动添加分隔符（如下划线），由用户控制

### 3. Templates 方法

```go
func (e *TablePrefixExtension) Templates() []*gen.Template
```

**返回值：**
- `[]*gen.Template`：包含表前缀逻辑的模板列表

**职责：**
- 加载并解析 `tableprefix.tmpl` 模板文件
- 将前缀配置注入到模板上下文
- 返回可供 Ent 代码生成器使用的模板对象

**实现细节：**
- 使用 `gen.MustParse` 确保模板解析成功
- 模板文件路径：`templates/tableprefix.tmpl`
- 模板名称：`tableprefix`

## 数据模型

### 模板上下文数据

模板在渲染时可以访问以下数据：

```go
type Graph struct {
    Config  *gen.Config      // 生成配置
    Nodes   []*gen.Type      // 所有实体类型
    Schemas []*load.Schema   // 所有 Schema 定义
}
```

**关键字段：**
- `$.Config.Package`：生成代码的包路径
- `$.Nodes`：所有实体节点的列表
- 每个 Node 包含：
  - `Name`：实体名称（如 "User"）
  - `Table`：默认表名（如 "users"）
  - `Package`：实体所在包名

### 前缀配置传递

前缀通过扩展实例传递到模板：

```go
// 在模板中可以通过扩展访问
{{ $ext := .Extension }}
{{ $prefix := $ext.Prefix }}
```

## 模板设计

### tableprefix.tmpl 结构

```gotmpl
{{/* 定义模板块 */}}
{{ define "tableprefix" }}

{{/* 获取包名 */}}
{{ $pkg := base $.Config.Package }}

{{/* 生成文件头部 */}}
{{ template "header" $ }}

{{/* 导入必要的包 */}}
import (
    "{{ $.Config.Package }}/{{ $pkg }}"
)

{{/* 为每个实体生成表名钩子 */}}
{{ range $n := $.Nodes }}
    {{/* 生成 Table() 方法覆盖默认表名 */}}
    func ({{ $n.Name }}) Table() string {
        return "{{ $.Extension.Prefix }}{{ $n.Table }}"
    }
{{ end }}

{{ end }}
```

**模板功能：**
1. 遍历所有实体节点
2. 为每个实体生成 `Table()` 方法
3. 在方法中返回带前缀的表名
4. 利用 Ent 的钩子机制覆盖默认表名

### 生成代码示例

假设有 `User` 和 `Post` 两个实体，前缀为 `app_`，生成的代码：

```go
// Code generated by ent, DO NOT EDIT.

package ent

import (
    "your-project/ent"
)

// Table 返回 User 实体的表名
func (User) Table() string {
    return "app_users"
}

// Table 返回 Post 实体的表名
func (Post) Table() string {
    return "app_posts"
}
```

## 错误处理

### 模板解析错误

**场景：** `tableprefix.tmpl` 文件不存在或语法错误

**处理：**
- 使用 `gen.MustParse` 在启动时立即失败
- 提供清晰的错误信息指示模板文件位置
- 在开发阶段尽早发现问题

### 前缀验证

**场景：** 用户提供的前缀包含非法字符

**处理：**
- 在 `WithTablePrefix` 函数中进行基本验证
- 检查前缀是否为合法的 SQL 标识符
- 如果验证失败，返回错误或使用默认值

**验证规则：**
- 允许字母、数字、下划线
- 不以数字开头
- 长度限制（建议不超过 20 个字符）

### 空前缀处理

**场景：** 用户传入空字符串作为前缀

**处理：**
- 允许空前缀，此时不修改表名
- 模板中检查前缀是否为空
- 如果为空，直接返回原始表名

## 使用示例

### 基本使用

在 `ent/generate.go` 文件中：

```go
//go:build ignore

package main

import (
    "log"
    
    "entgo.io/ent/entc"
    "entgo.io/ent/entc/gen"
    "github.com/wuwuseo/ent"
)

func main() {
    err := entc.Generate("./schema", &gen.Config{
        Target: "./ent",
    }, entc.Extensions(
        ent.WithTablePrefix("myapp_"),
    ))
    if err != nil {
        log.Fatalf("running ent codegen: %v", err)
    }
}
```

### 多环境配置

根据环境使用不同前缀：

```go
func main() {
    prefix := os.Getenv("TABLE_PREFIX")
    if prefix == "" {
        prefix = "dev_"
    }
    
    err := entc.Generate("./schema", &gen.Config{
        Target: "./ent",
    }, entc.Extensions(
        ent.WithTablePrefix(prefix),
    ))
    if err != nil {
        log.Fatalf("running ent codegen: %v", err)
    }
}
```

### 与其他扩展组合

```go
func main() {
    err := entc.Generate("./schema", &gen.Config{
        Target: "./ent",
    }, entc.Extensions(
        ent.WithTablePrefix("app_"),
        // 其他扩展...
    ))
    if err != nil {
        log.Fatalf("running ent codegen: %v", err)
    }
}
```

## 性能考虑

### 代码生成性能

- 模板解析在启动时执行一次，不影响运行时性能
- 模板渲染复杂度为 O(n)，n 为实体数量
- 对于大型项目（100+ 实体），生成时间增加可忽略不计

### 运行时性能

- 生成的 `Table()` 方法返回常量字符串
- 无运行时计算开销
- 不影响查询性能

## 扩展性设计

### 未来可能的增强

1. **动态前缀**：支持根据实体类型使用不同前缀
2. **前缀模板**：支持更复杂的命名规则（如 `{env}_{app}_{table}`）
3. **后缀支持**：除了前缀，也支持表名后缀
4. **命名转换**：支持驼峰到下划线等命名风格转换
5. **配置文件**：从配置文件读取前缀设置

### 扩展点

- `TablePrefixExtension` 可以添加更多配置字段
- 模板可以访问扩展的所有公开字段
- 可以创建多个模板文件处理不同场景

## 依赖关系

- 最低 Ent 版本：v0.10.0（引入扩展机制）

## 安全考虑

### SQL 注入防护

- 表名在代码生成时确定，不接受运行时输入
- 前缀在编译时配置，不存在注入风险
- Ent 框架本身处理 SQL 转义

### 命名冲突

- 确保前缀不会导致表名超过数据库限制（通常 64 字符）
- 避免使用数据库保留字作为前缀
- 建议使用有意义的短前缀（如 `app_`、`v2_`）
